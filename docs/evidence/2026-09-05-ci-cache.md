# CI cache optimization checks — 2026-09-05 Pacific

Status: implementation and local/Linux integration verified; hosted cold/warm
cache timing comparison remains pending. The [CI contract](../module-appliance-ci.md)
owns cache contents, invalidation and trust boundaries.

The [first hosted image build](2026-09-05-github-image.md) spent 741.53 seconds
extracting Ubuntu and 304.84 seconds installing runtime packages. In the next
run, the pinned builder container took 175 seconds. These are the measured
targets; the number of workflow steps alone is not a duration measurement.

The optimization reuses container layers and pristine Ubuntu extraction,
with exact input keys and no configured Player/root or deployment material in
the base cache. Runtime packages, revision-specific Player installation,
signing, finalization and e2e still execute. Build and boot stay on one runner,
avoiding an intermediate 5.9 GB raw disk transfer. Standard checks now run once
per PR update instead of once for its push and again for the PR event.

Executed verification:

- **811 full PostgreSQL-backed tests passed / 10 host-specific skips / 4
  dependency warnings**, in 101.25 seconds. Six skips require GNU tar for cache
  round trips; four are the existing Linux image tools, TFTP and root UID gates.
- **11 cache tests passed in the existing ARM64 Linux builder**, including
  actual GNU tar restore with non-root numeric ownership, modes, hardlinks,
  absolute OS symlinks, xattrs, ACLs and a device node. Fault cases cover stale
  fingerprints, changed archive bytes, traversal, symlink-parent writes,
  configured roots, partial extraction failure, interruption cleanup and
  optional publication failure. No manual Pi image build was performed.
- The revised central container built and imported `central.app`, `media.worker`
  and `player.service` without network access. It retained FastAPI 0.115.12 and
  Photo Wall 0.1.0. An application-only change in a separate disposable context
  reused the dependency-install layer (`CACHED`) and rebuilt only the project
  install in 1.4 seconds. This measures local layer reuse, not remote cache
  transfer or a hosted image speedup.
- Ruff, repository documentation links and both workflows passed validation.
  Workflow validation used checksum-verified official actionlint 1.7.12;
  optional ShellCheck integration was disabled because it was unavailable.

The first optimized hosted run must populate its caches. Subsequent evidence
must record cache hit/miss, restore/save durations, build phase elapsed times,
the exact source/image identity and the e2e result before claiming an overall
speedup. A cache hit does not substitute for artifact or boot qualification.

## Standard media-check cache follow-up

The media Docker build now installs FFmpeg in a source-free stage and copies
the shared application's `/app` tree at the same absolute path. Standard
GitHub checks populate an AMD64 BuildKit cache through `media-test`, then load
the central and worker targets on the same builder. Compose uses their
verified project-specific image names with `--no-build`; the conversion check
runs the existing test image with networking disabled. The hosted behavior
and transfer savings of this additional scope remain pending.

Actual local ARM64 validation of this change:

- The first media package layer completed in **24.6 seconds**. A second build
  from a separate context with only a comment added to `media/__init__.py`
  marked the entire FFmpeg installation layer **CACHED**. Its application
  install completed in **1.3 seconds**. These are local layer measurements,
  not an overall hosted speedup.
- **55 Linux conversion tests passed in 104.47 seconds** in the restructured
  test image, with networking disabled.
- The production worker imported central, worker and Player modules as UID
  10001 using `/app/.venv/bin/python`; it could write its media directory,
  ran FFmpeg 7.1.5 and contained no pytest dependency. The central target
  imported successfully as UID 10001 and contained no FFmpeg binary.
- Compose configuration resolved the exact preloaded central/worker names.
  Ruff, all 53 documentation link sets and actionlint passed.

The previously pushed `6a101a9` standard GitHub run separately passed
**772 tests / 51 explicit skips**, then **55 Linux conversion tests**. That
run predates this media-stage/standard-workflow extension.
