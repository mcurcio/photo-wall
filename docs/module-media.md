# Central media module

Status: accepted for adapter/worker implementation, 2026-09-05. Root ratifies the stated SourceSpec and initial limits/profile bounds; inspector/build details remain to be verified during implementation. This document records source inspection and a design, **not** completed Immich, conversion, network-isolation, or physical qualification. It narrows D06/D07 and the media portion of D11/D12 without changing [requirements](requirements.md). [Decision 0001](decisions/0001-mvp-time-recovery-and-module-contracts.md), [the execution contract](execution-contract.md), and [the Planner contract](module-planner.md) own time, recovery, selection, and content-lock policy.

## Responsibility and decomposition

The central application owns immutable source definitions, live metadata membership, planning, authorization, and all PostgreSQL schema/repository methods. One separately supervised Python media worker refreshes sources, acquires requested originals, probes/converts them, and publishes immutable ready variants through that repository. The authenticated Photo Wall gateway streams those local variants. No conversion runs in API requests, the scheduler, or the Player. No upstream URL, ID, query, credential, redirect, or SDK enters Player configuration or protocol.

Disjoint implementation leaves can follow this contract:

| Leaf | Owns | Inputs and results |
|---|---|---|
| `media/immich.py` | Versioned upstream transport and response normalization | Connection configuration + `SourceSpec` -> bounded refresh result; selected immutable upstream revision -> bounded original byte stream. No SQL, Frame policy, or Player API. |
| `media/prepare.py` | Probe, original validation, conversion, and recipe identity | Local original + expected metadata + recipe + resource limits -> exact `Variant`, original hashes, coded failure. No upstream transport or assignment authority. |
| `media/worker.py` | Poll/lease/retry/cleanup orchestration | Repository interfaces + adapters + explicit clock -> refresh publication/job result. No independent source selection. |
| Central repository and gateway, orchestrator-owned | Transactions, quotas, blob references, source/asset tables, authorized local delivery | Persisted publication and commitment interfaces below. All SQL and wire contract changes remain with this owner. |
| Integration harness | Disposable real upstream and synthetic media | Separate fixture credentials; network denial and success/fault evidence. It does not mutate a user's existing Immich. |

`Candidate` and `CatalogSnapshot` stay defined only in [central/catalog.py](../central/catalog.py); `Variant`, `Plan`, and `Layer` stay in [contracts/models.py](../contracts/models.py). `Candidate.original_width/height` mean the original's display-oriented dimensions, before any Immich edit or Photo Wall scaling. The Planner remains the sole owner of Frame compatibility and ranking. The adapter does not duplicate portrait/40-inch policy.

## Transport API and serialization

Implemented transport leaf: [media/models.py](../media/models.py) and [media/immich.py](../media/immich.py). It uses the existing httpx/Pydantic dependencies and [Clock](../contracts/time.py); it adds no database, worker loop, FFmpeg, or Player dependency. Its executed checks are synthetic MockTransport tests in [tests/test_immich.py](../tests/test_immich.py); the real-instance procedure below remains a separate integration gate.

`ImmichClient(config, *, limits=MediaLimits(), clock=SystemClock(), transport=None)` owns an `httpx.AsyncClient`, disabling environment proxies and redirects. Inject `httpx.MockTransport` for tests. It supports an async context manager or explicit `await close()`. Its public operations are:

* `await check_connection() -> None`: require the declared server version and authenticated `/users/me` UUID to match configuration. It does not claim that a subsequent asset download permission has already passed.
* `await refresh(spec: SourceSpec) -> RefreshResult`: check the connection, execute both bounded discovery/EXIF walks, and return one bounded snapshot plus central metadata and diagnostic counts. No automatic retry or state survives the call. Upstream/monotonic-clock failures return a non-ok snapshot with no selectable partial assets; a nonfinite UTC sample at entry raises coded `MediaError("clock_invalid")` because no valid observation instant can be recorded.
* `await download_original(asset: OriginalAsset, destination: Path) -> DownloadedOriginal`: revalidate version/owner, selected asset metadata, and immutable original identity; stream only an exact original into an absent caller-selected private staging path. Return its path, size, SHA-1, and SHA-256 after validation/fsync. An existing file or symlink is never replaced. On failure/cancellation remove only the partial created by that call; `staging_cleanup` explicitly tells the owner cleanup failed and its byte reservation must remain.

`MediaError` contains only `code` and `status` (`unavailable`, `permission`, or `incompatible`); check/download raise it for expected faults. Transport exceptions are suppressed rather than included in error text. There are no implicit retries. Hard asyncio wall deadlines surround streaming operations, with additional injected monotonic-clock checks for simulation; socket connect/read/write/pool timeouts are independently bounded. CPU-bound parsing is bounded by the JSON byte limit. Invalid caller models still use Pydantic validation; connection validation hides input values in its displayed errors.

Persistence serialization is explicit:

| Model | Durable/caller representation |
|---|---|
| `SourceSpec` | Use `model_dump(mode="json", by_alias=True)` so the serialized version key is `schema`; constructor accepts `schema_version` as well. Restore with `SourceSpec.model_validate`. Definition keys are exactly the documented source fields; no upstream credential is present. |
| `ConnectionConfig` | `connection_id`, `base_url` (literal HTTP(S) `/api` base), `owner_id`, `api_key: SecretStr`, `allow_http=False`, optional `ca_file: Path`. Caller loads the API key from its private runtime secret file. The key is excluded from repr and serialization; serialized settings alone cannot reconstruct an authenticated connection. HTTP requires explicit fixture/private-network opt-in. |
| `OriginalAsset` | Central-only `model_dump(mode="json")` contains `connection_id`, canonical `upstream_id`, hex `original_sha1`, `kind`, `raw_width`, `raw_height`, integer EXIF `orientation`, UTC `captured_at`, optional `file_size`, and video-only positive `duration`. Restore with `OriginalAsset.model_validate`. It contains no raw response, owner, path/filename, GPS, face, or secret fields. |
| Computed original properties | `asset_id` is `"asset-" + SHA256(canonical JSON [connection_id, upstream_id, original_sha1])`; the shared helper is `asset_identity`. `original_width/height` apply EXIF axis swapping once. These properties are derived again after restore. `candidate` supplies a neutral `Candidate` with `variant=None`; verified variant attachment remains repository/worker ownership. |
| `RefreshResult` | `snapshot: CatalogSnapshot`, `assets: tuple[OriginalAsset,...]`, `diagnostics: tuple[Diagnostic(code,asset_id?),...]`, and `counts: RefreshCounts(discovered,valid,pending,rejected,duplicates,examined,search_requests,json_bytes)`. Arrays are bounded; diagnostics expose neutral IDs only. Persist source snapshot and original records centrally; never serialize the whole result to a Player. |

The adapter reports `unsupported_version`, `owner_mismatch`, `upstream_schema`, `upstream_pagination`, `upstream_permission`, `upstream_redirect`, `upstream_encoding`, `upstream_timeout`, and `source_limit` distinctly. Per-asset failures include `metadata_invalid`, `metadata_pending_or_changed`, `asset_oversize`, `asset_missing`, `asset_permission`, `asset_changed`, and `asset_integrity`. Missing/all-invalid metadata also carries aggregate `metadata_pending_or_invalid`. The worker/repository owns retry time and exclusion of failed unsecured candidates; transport does not reroll assignments or release pins. Original byte geometry/profile verification remains the subsequent preparation leaf's responsibility.

## Declared upstream and source definition

Support exactly Immich **v2.5.6**, tag resolved during this design to commit `3be8e265cd5bd6ca921ff9e665e274c5de45caa0`. A different `{major,minor,patch}` yields `incompatible/unsupported_version`, pending a separately tested adapter version. The API base is `/api`. These are inspected tagged contracts, not assumed compatibility with `v2`, `release`, or `latest`. [Tagged OpenAPI](https://github.com/immich-app/immich/blob/3be8e265cd5bd6ca921ff9e665e274c5de45caa0/open-api/immich-openapi-specs.json).

Central-only strict immutable `SourceSpec` v1 has:

```json
{
  "schema": 1,
  "source_ref": "holiday:1",
  "connection_ref": "library-main",
  "favorites": true,
  "captured_from": 1796083200.0,
  "captured_until": 1798761600.0,
  "media_types": ["image", "video"]
}
```

`favorites` is boolean or null (no favorite filter); capture limits are optional finite UTC instants with `from < until`; `media_types` is a nonempty unique subset of image/video. Capture membership is `[captured_from, captured_until)`. The operator input normalizes explicit-offset dates to UTC using the existing time policy. `source_ref` names an immutable authored revision and is snapshotted with admitted Scenes; a changed query creates a new revision. Refresh results never edit it. Limits/refresh cadence are operational configuration, independent of the Scene lifetime and preparation horizon.

Runtime connection configuration contains only central settings: a stable connection ID, API base URL, trusted CA settings, API-key file path, and owner account UUID. It is supplied through deployment files/secrets outside Git. Resolve/verify that UUID through `GET /users/me` at connection validation. The runtime key needs `user.read`, `asset.read`, and `asset.download`; it gets no upload, modification, deletion, sharing, or administration permissions. Never put its value in a source definition, DB diagnostic, command argument, or log. The integration fixture's independent administrative key is not the runtime key.

MVP scope is the authenticated account's own timeline-visible originals. Exclude partners, archives, hidden/locked/trash/offline assets, audio/other media, arbitrary query expressions, semantic search, faces, shared links, and Immich edits. Enforce `ownerId == configured_owner_id` locally: tagged search can include timeline-enabled partners, and favorite response semantics differ for nonowners. The worker performs no Immich writeback. [Search service](https://github.com/immich-app/immich/blob/3be8e265cd5bd6ca921ff9e665e274c5de45caa0/server/src/services/search.service.ts), [asset response mapping](https://github.com/immich-app/immich/blob/3be8e265cd5bd6ca921ff9e665e274c5de45caa0/server/src/dtos/asset-response.dto.ts).

| Request | Tagged contract and adapter use |
|---|---|
| `GET /server/version` | Public endpoint; require a bounded JSON object containing integer `major=2, minor=5, patch=6`. Check on worker startup and before each refresh cycle. |
| `POST /search/metadata` | `MetadataSearchDto`; permission `asset.read`; request `page`, `size`, `order:"desc"`, one `type:"IMAGE"` or `"VIDEO"`, `visibility:"timeline"`, `isOffline:false`, `withDeleted:false`, optional `isFavorite`, `takenAfter`, `takenBefore`. Never accept an arbitrary upstream body from a Scene. |
| `GET /assets/{uuid}` | Permission `asset.read`; only a validated selected UUID. Recheck metadata immediately before an original acquisition to catch deletion, checksum changes, and loss of access. |
| `GET /assets/{uuid}/original?edited=false` | Permission `asset.download`; expect a successful byte response. Do not request thumbnails, `key`, or `slug`. The tagged original handler serves original/edited paths according to that flag; shared links force edited behavior and are outside the adapter. |

These endpoints and permissions were checked against the [tagged OpenAPI](https://github.com/immich-app/immich/blob/3be8e265cd5bd6ca921ff9e665e274c5de45caa0/open-api/immich-openapi-specs.json) and [original handler](https://github.com/immich-app/immich/blob/3be8e265cd5bd6ca921ff9e665e274c5de45caa0/server/src/services/asset-media.service.ts). The response checksum is base64 SHA-1 of the original, not a Photo Wall SHA-256. Validate its decoded length and use it for upstream revision/transfer consistency; calculate Photo Wall's own SHA-256 over acquired and prepared bytes.

## Live discovery, pagination, and metadata

A refresh requests page 1 for each media type at the configured initial `page_size`. If `assets.nextPage` is `"2"`, it discards that probe and requests page 1 again at `min(max_candidates + 1, 1000)`. Only a response with `nextPage == null` can establish membership; a still-incomplete response fails with `source_limit`. Validate `assets.items` as an array, `count == len(items) <= requested_size`, bounded fields, UUIDs, enums, finite timestamps, and no duplicate IDs in a complete response. The response's `assets.total` is not a complete count: this tag assigns both `total` and `count` to the page length. [Search response implementation](https://github.com/immich-app/immich/blob/3be8e265cd5bd6ca921ff9e665e274c5de45caa0/server/src/services/search.service.ts).

Pagination is offset based, sorted only by `fileCreatedAt`, with no transactional snapshot or ID tie-break. The real fixture demonstrated permanent omissions under quiescent state when equal timestamps cross offsets. Therefore the adapter never continues by offset. The supported source bound is at most 1000 candidates, matching the API request-size ceiling; broader queries fail explicitly and require narrowing. All probe rows still count against aggregate work limits. Separate discovery and metadata responses can differ during concurrent edits, so no atomic upstream snapshot is claimed. Every refresh starts again and includes newly uploaded older photos and favorite changes. Budget exhaustion publishes no partial membership and preserves existing execution locks. [Tagged pagination](https://github.com/immich-app/immich/blob/3be8e265cd5bd6ca921ff9e665e274c5de45caa0/server/src/repositories/search.repository.ts).

`withExif:true` uses an **inner join**, excluding assets without an EXIF row. `hasMetadata:true` is not a completeness signal in the normal response mapper. To distinguish a successful empty query from pending/invalid metadata, perform a discovery walk with `withExif:false` and a second bounded walk with `withExif:true` using the same query. Discovery determines known membership; only matching IDs from the EXIF walk can become candidates. Metadata-only new IDs wait for the next refresh. A discovery ID missing from the second walk gets `metadata_pending_or_changed`, not guessed geometry. Repeated refresh supplies eventual convergence; a missing ID from one walk is not proof of hard deletion. Metadata per selected original is additionally rechecked before download. [Database query builder](https://github.com/immich-app/immich/blob/3be8e265cd5bd6ca921ff9e665e274c5de45caa0/server/src/utils/database.ts).

For each owned member, validate `type`, `fileCreatedAt`, `checksum`, `ownerId`, `visibility`, `isFavorite`, `isTrashed`, `isOffline`, and EXIF raw width/height/orientation/file-size. `takenAfter`/`takenBefore` are inclusive upstream; apply the authoritative local half-open interval against `fileCreatedAt` after transport. `localDateTime` is timezone-agnostic display grouping and must not define chronological capture or scheduling time. Null, nonintegral, nonpositive, oversized, or inconsistent dimensions are a metadata error. `orientation` is null or a string representation of EXIF 1–8; null means absent orientation, normalized to identity, and other strings are invalid. Swap raw width/height for 5–8 exactly once. Do not use the top-level `width/height`: the tagged metadata service deliberately preserves values modified by Immich edits. [Metadata extraction](https://github.com/immich-app/immich/blob/3be8e265cd5bd6ca921ff9e665e274c5de45caa0/server/src/services/metadata.service.ts), [orientation helper](https://github.com/immich-app/immich/blob/3be8e265cd5bd6ca921ff9e665e274c5de45caa0/server/src/utils/asset.util.ts).

Publication is one central transaction after all required pages complete. `RefreshResult` contains `CatalogSnapshot`, bounded coded diagnostics, discovered/valid/pending/rejected counts, and source refresh identity. A genuine zero discovered owned members is `ok` with no candidates. Nonempty discovery with no usable metadata is `incompatible` with `metadata_pending_or_invalid`; partially usable results may be `ok` with explicit per-asset metadata diagnostics/counts. Unsupported media profiles and Frame ineligibility have separate diagnostics. Any request, protocol, or page-budget failure publishes a non-ok snapshot; previously successful data may remain for operator diagnosis but must not masquerade as a fresh selectable pool. Existing Planner behavior already excludes non-ok snapshots.

The central asset revision key is `(connection_id, upstream_uuid, upstream_original_checksum)`, mapped to an opaque Photo Wall `asset_id`. Metadata revisions are separate from original-byte revisions. Changing a favorite or caption must not unnecessarily duplicate prepared bytes; changing an original checksum creates a new immutable asset revision. A central recipe version plus original identity selects a prepared variant; old exact variants remain independent objects while referenced. `Candidate.variant` is populated only from a complete ready record whose verified original metadata agrees with the candidate.

## Operational bounds and failure classes

Proposed initial defaults, to be configured and tested rather than treated as measured performance promises:

| Budget | Initial value and behavior |
|---|---|
| Refresh | Every 30 s for active source revisions; serialized per source; 1,000 discovered members, page size 100, at most 40 search requests across both walks/types; 60 s total wall time per refresh. Stop on the first exceeded aggregate bound. |
| JSON transfer | 2 MiB per response; 32 MiB per complete refresh; read in bounded chunks and count decoded bytes. `Accept-Encoding: identity`; reject compressed response bodies in this adapter version. |
| HTTP | 3 s connect, 10 s per read inactivity, 15 s metadata request wall time; original download 120 s total. Deadlines use a supplied monotonic clock, not source timestamps. |
| Acquisition | At most 256 queued distinct original/recipe jobs globally; one active conversion initially; reserve staging before opening a stream. Original maximum 256 MiB. Reject advertised oversize before reading and enforce actual received bytes even without `Content-Length`. |
| Preparation | At most 64 million original pixels; video duration at most 300 s; one video stream; conversion wall time 180 s and process memory/CPU limits. Reject unsupported streams/profile instead of treating a thumbnail as an original. |
| Storage | 4 GiB aggregate managed central media bytes, including active reservations, originals, partials, prepared blobs, and cleanup-pending files; per-job reserve 256 MiB original + 256 MiB derivative. JPEG output maximum 16 MiB; MP4 maximum 256 MiB. Reject work when pinned bytes/reservations cannot fit. |
| Delivery | Full-file requests only in v1; maximum active transfer count 8 globally. Each descriptor/response has a hard 120 s lifetime and a 150 s database reference for cleanup margin; there is no transfer heartbeat or renewal. Player enforces its independent cache/download bounds. |

Use `httpx` with `follow_redirects=False`, `trust_env=False`, validated fixed base origin, explicit TLS verification, no source-supplied URL fragments, and `x-api-key` only toward that configured upstream. Every 3xx, including same-origin redirects, is `upstream_redirect`; never forward upstream headers or bodies to a Player. Reject credentials in base-URL userinfo and unexpected query/fragment. Deployment can deliberately use HTTP only on the isolated private integration network; appliance-facing Photo Wall traffic follows the existing HTTPS trust policy. A response `Content-Type` is a hint, not proof of safe media or matching bytes.

Map 401/403 to `permission`, unsupported version/schema/invalid pagination to `incompatible`, timeout/DNS/reset/429/5xx to `unavailable`. Never interpret them as empty. Selected-asset detail/original 400 becomes `asset_unavailable`, because this tag deliberately uses the same status for missing and inaccessible assets; do not infer which. Original 404/410 becomes `asset_missing`; download denial is `asset_permission`; checksum/length mismatch is `asset_integrity`; conversion and resource failures have separate bounded codes. Do not persist raw exception strings, URLs with credentials, request bodies, or upstream error bodies. [Tagged access check](https://github.com/immich-app/immich/blob/3be8e265cd5bd6ca921ff9e665e274c5de45caa0/server/src/utils/access.ts).

Retry transport failures with bounded backoff, initially 5/15/60 s, and capped `Retry-After`; attempts are separately leased and never run concurrently for one job. Invalid metadata, unsupported media, and integrity failures require a new refresh/revision or explicit retry after their recorded cooldown. Return failures to central coordination for Planner and Runtime ownership. During that cooldown, exclude the failed asset revision from **unsecured** dynamic/authored candidate inputs and report its code; otherwise the current Planner can repeatedly choose the same unavailable first alternative. Locked Layers are retained independently. No media worker retries authorize late execution or reroll a secured assignment.

## Original validation and preparation recipe

Generate Photo Wall derivatives from downloaded originals in this MVP; do not reuse Immich thumbnails or encoded-video output until their original/variant semantics have separate qualification. Originals remain central temporary/reusable cache data, not a mirrored library. Only planner-requested selections are acquired, including covered assignments needed for reveal, within the configured rolling horizon. Refreshing 1,000 metadata rows never means downloading 1,000 files.

Pin a recipe identifier over the complete conversion settings, FFmpeg build/configuration, and relevant package versions. The recipe initially supports opaque SDR JPEG/PNG still originals and ordinary SDR MP4/MOV H.264/HEVC video originals. Animated images, RAW/HEIC, HDR/HLG/PQ, non-sRGB/wide-gamut still profiles, unusual rotation matrices, and unsupported containers are explicit preparation failures, pending tested extensions. Silent SDR output is a restriction on accepted/converted profiles; merely setting a color tag does not convert HDR correctly. Untagged ordinary 8-bit JPEG is interpreted as sRGB under this declared input profile; reject a conflicting embedded profile. A bounded metadata inspector must validate the source profile; add a narrowly scoped decoder dependency if FFprobe cannot establish it rather than assume success.

First download into a private randomized staging filename, hash original SHA-1/SHA-256, verify the expected checksum and declared/received sizes, then probe. No upstream path or filename is used locally. Verify encoded raw dimensions against EXIF and inspect original orientation before acceptance; metadata-to-byte disagreement invalidates that candidate and triggers refresh. Still EXIF handling and video display-matrix handling require fixtures. Apply orientation exactly once with FFmpeg autorotation disabled, using a normalized transform selected by the media adapter. Suggested EXIF transform mapping:

| EXIF | Pixel transform after raw decode |
|---|---|
| 1 | Identity |
| 2 | `hflip` |
| 3 | `hflip,vflip` |
| 4 | `vflip` |
| 5 | `transpose=clock,hflip` |
| 6 | `transpose=clock` |
| 7 | `transpose=clock,vflip` |
| 8 | `transpose=cclock` |

For a video, normalize the original display matrix to this orthogonal representation and cross-check Immich's orientation; reject arbitrary matrix/shear rather than guess. Preserve the original display aspect ratio, including sample-aspect ratio; normalize derivative pixels to SAR 1. Output probing must establish upright dimensions and absence of a residual rotation matrix. Source portrait/quality eligibility remains based on original display dimensions, never on a crop or upscaled derivative.

Still recipe: orient, downscale without upscaling to maximum long edge 3,840 px, encode a single JPEG with fixed quality, strip inherited EXIF/location metadata, normalize the accepted SDR color profile. Video recipe: orient, downscale without upscaling to a configurable tested output bound, normalize to SDR BT.709/yuv420p, cap 30 fps, encode H.264 with `libx264`, MP4 `+faststart`, fixed CRF/preset/GOP/profile, and no audio/subtitle/data streams (`-map 0:v:0 -an -sn -dn -map_metadata -1 -map_chapters -1`). Initial bench recipe should target 1,920 long-edge, at most 2,073,600 pixels, H.264 High level 4.2. If its result falls below the Frame-required original quality floor, the Planner's existing variant check rejects it; do not upscale to manufacture readiness. Record the exact supported aspect/profile envelope during integration and physical tests before treating this starting recipe as appliance capacity.

Invoke FFmpeg/ffprobe as argument arrays with `-nostdin`, bounded logs, no shell, local staged inputs, explicit demuxer/protocol allowlists, and network protocols disabled. A URL in media must not become a nested network request. The conversion process gets only required read-only runtime files and its private staging directory; limit output file size, aggregate staging bytes, wall time, CPU, and memory independently. Kill/reap its process group on timeout/cancellation and remove partial output. FFmpeg's `-fs` is only a secondary stop condition; its documented behavior can exceed the requested size, so enforce the filesystem/process limit and postcheck too. [FFmpeg options](https://ffmpeg.org/ffmpeg.html), [filters](https://ffmpeg.org/ffmpeg-filters.html).

After conversion, probe and fully decode the output under the same limits; verify codec/container, stream count, SDR profile, dimensions, duration, frame-rate bound, orientation, and output byte cap. Hash final bytes, fsync the file, and publish to a canonical digest-derived path on the same filesystem. Only then can the repository atomically expose `Variant(sha256,size,media_type,width,height,duration)`. JPEG has `duration=None`; MP4 has a measured positive duration. This establishes prepared **bytes**, not a Player's decoder readiness, aggregate capacity, or execution commitment.

## PostgreSQL, file publication, and reference interface

The root-owned repository is the only SQL owner. Suggested logical records are `source_versions`, `source_refreshes`, `asset_revisions`, `media_jobs`, `media_blobs`, and `media_references`; exact schema naming is an implementation detail. A source's last successful membership and latest refresh status are separate. Blob identity/metadata are immutable. A job is unique for `(asset_revision, recipe_id)` and has `queued/running/retry/ready/failed` state, attempt generation, attempt expiry, bounded failure code, and reserved bytes. Procrastinate owns queue attempts and retry timing. References identify their typed owner and exact digest rather than only a source or Run.

Define these repository operations before delegation:

* `publish_refresh(source_ref, refresh_id, result, now)`: atomically replace a completed live working set/status and attach existing verified variants by immutable original/recipe identity. It does not delete referenced blobs or mutate admitted query definitions.
* `request_acquisitions(requests)`: idempotently create selected original/recipe jobs and defer their Procrastinate task through its external PostgreSQL connection in the same transaction. Reject the explicit job/count bound; never perform network or conversion inside the transaction.
* `claim_job(job_id) -> Lease | None`: lock only the exact job delivered by Procrastinate, increment its attempt token, and transactionally reserve the complete worst-case staging budget under the media quota lock. No row lock survives the transaction during conversion.
* `publish(lease, result)` and `fail(lease, code, retry=...)`: compare-and-swap on live attempt identity. An expired/stale task may clean its own staging files but cannot publish over a replacement attempt. Publication verifies expected original/recipe identity and transitions the blob/job atomically. A retry result is returned to Procrastinate, which applies the bounded 5/15/60-second schedule.
* `offer_plan_media(plan_identity, exact_layers, player_authority, now)`: authorize and pin every digest in the offered current plan **before** returning it to a Player. Limit offers to true projection intervals and record expiry; a digest alone is not authorization.
* `lock_secured(plan_identity, readiness, now)`: central coordination checks current epoch/revision/bindings and exact offered Layer under its transaction, inserts immutable assignment locks, and upgrades/reuses media references before dropping offer references. This happens on `secured` receipt, before formal commitment. Commitment is a separate transition.
* `open_authorized_blob(player, digest, now) -> ReadLease`: current nonretired Player, current Frame generations, and its live offer/assignment references must authorize that exact digest. Acquire an in-flight reference before opening a nonsymlink canonical regular file. Return coded errors and a read-only file descriptor, never an upstream locator.
* `release_owner(owner, reason, now)` and `collect_unreferenced(now)`: lifecycle/coordination explicitly release completed/cancelled/superseded work; timed offers and crashed transfer leases can expire. Garbage collection selects only unreferenced blobs while holding the same quota/reference lock.

All operations creating/removing blob references or reserving/evicting bytes serialize on one PostgreSQL advisory lock for the initial single-installation media store. Multiple references to the same digest count its bytes once. A plan offer pins bytes before download; a secured acknowledgment pins/locks the exact assignment before commit; active transfers independently pin their source file. Supersession cannot destroy a lock already secured on the Player but racing its acknowledgment: keep an offered revision's exact manifest and pin through a bounded readiness reconciliation/grace interval, accept only still-valid authority, and release it only after explicit supersession acknowledgment or execution lease expiry. The 30-second interval triggers reconciliation/degraded health, not silent release or rerolling of possibly secured content. Outstanding revision/byte limits apply backpressure until this uncertainty resolves. The existing content-lock policy is not weakened by a storage optimization.

Filesystem and SQL are not one transaction. Reserve before download; write/fsync/rename before committing readiness. Use a per-blob publication journal/record plus the quota lock to prevent GC from treating a live publication as an orphan. Worker restart reclaims expired attempts only after checking their authoritative lease; stale partial/orphan files remain byte-accounted until successfully deleted. Startup reconciliation verifies ready files against size/hash, invalidates corrupt ready rows, and reports failures to coordination. A rename-before-ready crash leaves an untrusted, accounted orphan, never a downloadable ready blob. A failed unlink retains accounting and refuses further acquisition if necessary.

GC has a durable `deleting` state: mark only an unreferenced blob while serialized with reference creation; new offers cannot reference it; unlink; then remove its accounting. A crash or unlink failure keeps it unavailable and accounted until reconciliation finishes. Quota reductions preserve all existing references and expose pressure rather than deleting pins. Originals may be discarded after verified variant publication when no job needs them; long Runs do not pin their history. Central cannot reconstruct a lost locked derivative from a changed upstream file and must report `blob_lost` while a healthy Player retains its valid local copy/fallback.

## Immutable Photo Wall delivery

The gateway route is the exact relative path generated by the existing `Variant` contract, `/v1/media/<sha256>`. It returns local immutable bytes with exact content length/type, ETag equal to the digest, no content encoding, no upstream-derived headers, and no `Location`. Accept Player bearer authentication through the central authority check on every request; unbound/retired/stale authority is denied even if the caller knows a digest. Use private cache policy. GET/HEAD may be supported; in v1 reject range requests explicitly rather than implement incorrect partial hash semantics.

A file descriptor and fixed transfer lease protect a stream from GC until its hard lifetime; the server releases it on completion, disconnect, error, or timeout. Revalidation on each request rejects new retired authority; it does not claim to revoke bytes already transferred. The Player rejects every 3xx and verifies exact bytes against its Variant before reporting secured. A gateway miss never downloads from Immich on behalf of that HTTP request and never redirects there. It returns `media_unavailable` and schedules appropriate central repair through module ownership.

## Disposable real-Immich integration fixture

No user library or credentials are needed. Build a dedicated Compose project from the **tagged** official Immich compose, retaining its compatible dependencies but removing public ports and fixed container names. Mount only newly created fixture volumes. Pin `ghcr.io/immich-app/immich-server:v2.5.6` by resolved digest before recording evidence. The official machine-learning service can remain disabled because this query subset does not use it; if omitted, explicitly disable/avoid ML jobs in fixture configuration and record that deviation. Do not silently omit dependencies and call it the official complete deployment. [Tagged compose](https://github.com/immich-app/immich/blob/3be8e265cd5bd6ca921ff9e665e274c5de45caa0/docker/docker-compose.yml), [official install guidance](https://docs.immich.app/install/docker-compose/).

|---|---|---|

Neither Immich nor its dependencies publishes host ports; Player containers have no host networking, host gateway mapping, Docker socket, proxy, or network-admin capability.
