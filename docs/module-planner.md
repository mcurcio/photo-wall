# Pure rolling Planner

Status: implementation contract accepted for the first MVP; its source input became the photo pools in delivery [4](roadmap.md#4-real-photo-sources) (pull request [#81](https://github.com/mcurcio/photo-wall/pull/81)). This is a central domain module; it does not acquire media, change Runtime, establish readiness, issue execution authority, or call devices. [The time/recovery decision](decisions/0001-mvp-time-recovery-and-module-contracts.md) and [execution contract](execution-contract.md) remain authoritative.

## Inputs, state and output

`project(runtime, now, *, bindings_by_player, source_pools, authored_candidates, locked_assignments, horizon_seconds=300, limits=PlannerLimits()) -> Projection` is stateless. Inputs are current `Runtime`, a finite UTC instant, Player-to-`OutputBinding` sequences, source-reference-to-`SourcePool` mappings (each Source revision's whole pool, read by `MediaRepository.source_pools_in` in the coordination transaction: one consistent read, no window and no limit), asset-reference-to-`Candidate` mappings for authored media, and assignment-ID-to-exact-`Layer` locks already accepted by central coordination. Shared catalog and transport models have their sole definitions in `central/catalog.py` and `contracts/models.py`.

`Projection` names `now`, `horizon_end`, and `valid_until` separately. It returns per-Player `PlayerProposal.layers`, central-only `AcquisitionRequest(asset_id, assignment_ids, earliest_start)` entries, central-only asset/assignment selection records, and coded diagnostics. It does not construct a `Plan`: epoch, revision, commitment, transactionality, current Frame authority and persistent locks remain coordination responsibilities. `PlanningError` and `PlanningBudgetExceeded` fail explicitly without partial proposals or external effects.

Runtime gains `timeline(start, end, max_events=10000)`: it restores a copy, reconciles the start, and returns settled immutable views at the start and every discrete lifecycle boundary before the end. It never samples at one-second intervals. An explicit transition/event budget includes catch-up and generated descendants, so tiny cycles and excessive child work fail instead of hanging. Timeline projection cannot affect current Runs, admissions, queues or recorded Actuators. Intent retains sampled opacity for current observation and also exposes authored base opacity and fade durations for execution layers.

## Preparation horizon and execution intervals

The configured preparation horizon bounds **assignment start times**, not a Scene's total lifetime. Include a currently active assignment or a future assignment whose true start is strictly before `now + horizon_seconds`; preserve its full half-open natural cycle/outro interval and media origin. A cycle/outro must be at most `limits.max_cycle_seconds` (300 seconds by default). Longer cycles fail explicitly; long-running Scenes use an unbounded sequence of bounded cycles. The horizon itself is configurable up to the limits' explicit maximum.

`valid_until` is the greater of the preparation-horizon end and included complete assignment ends, and can therefore extend by at most one bounded cycle. Ongoing assignments can start before `now`; Players must seek their true cycle media origin. No polling-dependent clipping changes IDs, fade timing, pinned locks, or authorization intervals. The host Plan validator permits a Layer that overlaps Plan validity and still requires its end to be inside the Plan's validity. This distinction is an MVP choice, not a numerical outage guarantee.

Assignment identity hashes Run ID, typed target, phase and original cycle interval. Selection does not participate in that identity: an unsecured assignment may change exact bytes, but a secured lock retains its exact variant/media identity and interval. Root/descendant arbitration metadata can be revised under a new Plan revision and renewed readiness; it is not a content lock. Root admission order and descendant order must both remain represented in per-Player layer stacking. A later descendant of an old background must not overtake a newer independent overlay. Unrelated and actuator-only targets never become implied display commands.

## Eligibility, selection and fallbacks

This module is the single owner of original-media eligibility. Landscape images are excluded from portrait Frames. Videos require the Frame video capability, and originals with fewer than 1080 pixels on their shorter side are excluded on Frames of at least 40 inches. A large derivative cannot rehabilitate an unsuitable original. Exact variants must have compatible media type and usable video duration; malformed prepared candidates are diagnosed rather than sent to a Player. Authored asset alternatives follow the same checks and stay on their authored Frame/role. Authored candidates are considered in authored order; source candidates are considered only for a dynamic contribution without authored alternatives.

A dynamic contribution's candidate pool is the union of the pools of the Sources it names, in the contribution's order, one candidate per asset ID (the first seen), newest first. Each Frame's contribution names its own Sources (Runtime's `source_refs` per target), so one Frame's Sources never mix into another's; the console writes the same Sources on every Frame of a Scene, so for every Scene it makes this is the Scene's pool. The Planner reads every photo in those pools: there is no window and no candidate cap (owner, 2026-10-09: "i dont want any limit on the count of a source"). It filters eligibility first, ranks by descending capture time and stable asset ID, and rotates by logical cycle index for variety. A check's newly confirmed photos enter the next unsecured cycle within the same Run. A source reference denotes an immutable authored query version; new query results remain live data. A pool whose check has not completed, or whose last check failed, still offers what it holds: the last pool keeps playing while Immich is down or the key is rejected (C7), because a pool row is a photo a check confirmed and a check removes photos only when it completes ([media module](module-media.md#live-discovery-pagination-and-metadata)). The diagnostics are `source_missing` (no pool for the reference), `source_not_ready` (no complete check yet and nothing found so far), `source_empty` (a complete check found nothing: truly empty), and, as before, ineligibility, absent authored alternatives and pending or failed preparation; the connection's own health says why a check failed.

`candidate_standing(candidate, profile)` is the planner's one per-candidate verdict for an eligible candidate, in its exclusion order: `failed_to_prepare` (a recorded preparation failure; the media repository's candidate hydration also records one for a failed job whose retry is not yet due), `preparing` (no variant yet), `no_compatible_variant` (a variant the profile cannot use), or `usable`. The pool drops `failed_to_prepare`; selection requests acquisition for `preparing` and diagnoses `variant_incompatible` for `no_compatible_variant`. The operator candidates route serves the same verdict ([authored media](module-authored-media.md)), so no caller restates the variant rule.

A selected eligible candidate without exact prepared bytes creates a bounded central acquisition request and no playback-ready Layer. A missing/empty/error contribution emits no replacement display command and a fallback diagnostic; the executor retains its authorized compatible still or configured local fallback under the recovery policy. The Planner never substitutes a different target or relaxes eligibility. Explicit authored opaque black produces an exact black Layer independently of media availability. Covered contributions remain in proposals for current-state reveal and transparency; only Runtime's target union is not sufficient to create a Layer.

## Locks and failure boundaries

Locked bytes, assignment/media identity and temporal/effect interval are carried forward only while their Runtime assignment still exists in this projection and its Player/output/Frame generation remains valid. Fresh priority/root/descendant arbitration metadata is recomputed while preserving the exact secured variant; coordination must issue a new plan revision and invalidate execution readiness as needed. Descendants use a durable per-root sequence so unrelated activation does not perturb their local order, while a future Program root can still acquire a different actual root order. Query deletion or an upstream outage cannot reroll it. A stale binding, interval, Run, or assignment key is diagnosed and excluded; authority epochs are checked by central coordination before passing locks. The caller must use the persisted adopted Runtime tree associated with the locks, which supplies fixed role and Scene-revision context; it must not pair arbitrary replacement definitions with old locks. A later central-only durable lock record may carry an adopted-definition digest. Changed equipment profiles/calibration require coordination to revalidate original-media suitability and invalidate incompatible execution readiness before passing locks; exact bytes remain pinned until explicit release. Locks from a cancelled or completed contribution do not extend its lifetime or pin its history.

The Planner explicitly bounds horizon length, cycle length, Runtime transitions (including simultaneous Program admissions), assignments, sources, authored reference counts (`max_authored_refs`, 10,000), and acquisition count. It does not bound the number of pool candidates: a budget that cut a pool before the fit test could starve a portrait Frame. Subnormal cycles that exceed finite arithmetic fail with the same explicit Runtime budget error. It validates budgets before broad selection work and deduplicates acquisitions across covered/uncovered assignments and Players. Budget exhaustion returns no partial plan. No database, network, filesystem, media worker, or physical-device access exists here.

## Required evidence

Tests cover source changes within one Run, pre-lock replacement versus post-lock deletion, source errors versus empty pools, original-versus-upscaled eligibility, authored alternatives and fixed roles, missing variants and bounded acquisition, current-cycle origins and stable fade/lock intervals, covered layers, black versus fallback, short delayed children, projection purity, stale bindings and cancelled locks, stable precedence, and each explicit budget. These are simulated central planning checks and do not establish real Immich, media preparation, Player readiness or visible output.
