# Player execution module

Status: implemented platform-independent execution leaf; recording evidence only.
Owning policy: [decision 0003](decisions/0003-coordination-and-player-execution.md).

`player/executor.py` accepts authenticated central authority and exact assignments, enforces leases and revisions, owns cache-pin intent and durable reconciliation state, and drives a renderer. It never selects media or accesses central domain modules. `player/rendering.py` owns the renderer protocol and deterministic recording adapter; a later native adapter owns GTK/GStreamer.

## API and threading

The constructor is `Executor(player_id, cache, renderer, clock, mapping, state_path, prepare_lead=5)`. Configuration uses the shared `PlayerConfiguration` envelope (Player/epoch/configuration revision, current Output bindings and enabled Outputs). Bound but unvalidated Outputs support calibration in black fallback; only explicitly enabled Outputs accept playback authority.

- `accept_configuration(configuration) -> bool`, `accept_plan(plan) -> bool`, and `accept_commit(commit) -> bool` accept only externally authenticated models. Exact duplicate messages are idempotent; stale or mismatched authority is rejected with `AuthorityError`. A cold executor accepts only a newer centrally established epoch than its durable predecessor.
- `acquire(assignment_id, chunks) -> bool` and `verify_secured() -> None` are worker operations. Acquisition persists ownership intent, releases the executor lock before consuming the supplied iterator, and rechecks assignment authority before reporting success. Verification hashes exact cached bytes away from the rendering thread and invalidates stale preparation/commit state on corruption.
- `maintain_cache() -> None` is a worker operation that establishes retained-picture pins before releasing expired assignment pins. Durable intent precedes every cache pin; restart can reconcile interrupted publication. It may run after each tick and control message.
- `prepare_imminent() -> None` and `tick() -> tuple[Observation, ...]` run on the renderer's owning thread. They perform no downloads or cache hashing. Renderer preparation is bounded/nonblocking and may report pending. A successful preparation is distinct from whole-Player capacity and successful presentation.
- `readiness() -> Readiness` returns an immutable snapshot with an increasing epoch-local sequence. Each Commit references the exact `readiness_sequence` used centrally. The executor retains at most 128 snapshots, correlates them to per-assignment readiness generations, and rejects revoked snapshots after preparation/clock/capacity recovery. `invalidate(assignment_ids)` revokes preparation and execution while preserving secured identity for recovery; `cancel(assignment_ids)` and `release(assignment_ids)` terminate that assignment authority and defer cache cleanup to the worker.

Renderer calls use immutable `LocalLayer` (exact Layer, local path, current position, effective alpha) and `OutputComposition` (binding/effective calibration, ordered layers, explicit fallback status). `prepare(layer)` returns `PrepareResult` (prepared/pending/failed); `capacity(compositions)` returns `CapacityResult`; `present(composition)` returns `PresentationResult` (presented/pending/failed). Replacement preparation never clears prior output. Recording capacity initially permits four simultaneously resident media assignments and is explicitly unqualified.

## State and recovery

A private JSON state file records version, Player, epoch, config/plan revision, accepted Plan, cancelled assignments, and every pin owner before its first publication. Atomic temporary write, fsync, replace and parent fsync make each update durable. A partial write never replaces the last complete state. The cache independently commits exact bytes and pins; the durable intent bridges these transactions. Playback permission, preparation, observations, monotonic deadlines and retained picture permission are process-local. Restart displays black and cannot replay persisted plans; old pins remain protected until fresh central reconciliation retires their epoch.

Within a live epoch the plan ID is stable, revisions increase, and exact duplicate messages are harmless. Configuration and per-Output configuration/generation changes invalidate incompatible preparation, commits and retained pictures. A secured assignment's exact bytes and media identity cannot be changed by a rolling revision. Omitted secured assignments remain inactive lease records until explicit release or expiry; absence from new readiness is not proof of release. Cancellation tombstones prevent an older in-flight download or later duplicate plan from resurrecting authority. A new epoch clears prior execution and observations.

A currently executing unchanged assignment remaining in the full current-state Plan keeps its original authorized layer metadata and execution lease across rolling revisions. Omission from a newer Plan revokes execution immediately while preserving the inactive byte lease; this allows cancelled overlays to reveal underlying current content. Fresh metadata and a renewed lease take effect only after another valid Commit. This lets ordinary offer renewal preserve visible output without silently extending old authority. The original assignment pin remains protected until the worker confirms the dedicated retained-picture pin, including when rendering creates retention during an in-progress worker maintenance snapshot.

## Timing, continuity and failures

Only active committed layers execute; preparation is restricted to current/imminent work, initially five seconds ahead. Readiness gates use the injected clock mapping; stale/stepped clocks invalidate new work while successful visible authorized content remains. A pre-start grant delivered after its intended start is rejected; central must authorize the current logical position again. Tick rechecks clock/capacity and prepares newly visible layers at their current position. Layer start/end/media origin remain unchanged across rolling plans. Ordering is `(priority, root_order, admission_order)`; alpha uses original fades and position uses original media origin, including covered videos. Opaque black is a real layer, and zero-alpha layers reveal what lies underneath.

A successful compatible full-opacity still with central `retain_on_expiry` permission can become one retained picture per Output/Frame/generation. Mere cache presence or preroll cannot become fallback. Recoverable preparation/presentation failures retain valid output; expired videos, overlays and plans cannot remain active. A retained compatible still or local black replaces expired authority, with fallback observations. A pending/failed retained-picture prepare or presentation falls through to explicit black; the executor updates observations only after the renderer reports successful presentation. Binding replacement drops the old retained permission. Calibration preview expiry uses its explicit UTC lease locally and returns to committed calibration during an outage. Expired noncurrent decode resources are released, and recording capacity includes actual resident current/replacement resources.

Tests cover two Outputs and foreign Player rejection, secured-before-commit pins, imminent versus future preparation, capacity and async pending, stale messages, clock loss, covered-video current seek, original fades, decode/download/cache failures, overlay/plan expiry, local preview expiry, cancellation during streaming, warm outage and cold-restart reconciliation. These checks establish simulated execution semantics only; they do not establish native rendering, Pi capacity, PXE, HDMI continuity or visible synchronization.
