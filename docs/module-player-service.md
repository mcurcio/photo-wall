# Single-process Player control service

Implementation contract, 2026-09-05. The service composes neutral [enrollment](decisions/0002-registry-and-enrollment.md), [Executor](module-player-execution.md), cache and [native rendering](module-native-renderer.md). It owns networking, common public configuration, private identity persistence, reconnect policy and worker scheduling. It never imports central or media packages, inspects upstream assets, or selects media.

Common configuration specifies one trusted central HTTPS origin, public CA path, existing state directory, cache quota and native resource limits. Explicit HTTP is available only for isolated fixture development. Strict bounded JSON rejects unknown fields, credentials in URLs, query fragments and non-origin base paths. Output identity comes from Linux DRM connector observations, at most two HDMI connectors; disconnected connectors remain stable observations. The same configuration works on all Players. Platform services supply Wayland app-ID routing from these observed connector names.

Generate an Ed25519 key once using private atomic/fsynced storage on the owned state volume, with symlink, ownership and mode checks. Do not replace an existing invalid key silently. Unusable persistence generates an ephemeral key and declares signed `persistence=volatile`; that process only registers and reports the storage fault and never constructs an execution cache. On durable startup, re-enrollment with the existing key obtains a fresh epoch before accepting execution, so previous cached bytes cannot restore previous authority. Bearer tokens remain private in process memory.

The GTK/GLib main thread owns Renderer and all control-message application. An asyncio network thread owns authenticated bounded HTTP/WebSocket connections; a single media worker thread serializes download/cache work. Queues are bounded. State snapshots can coalesce, but an epoch/configuration change, revocation, or full-plan omission must never be discarded by coalescing. Apply each accepted state and its immediate prepare/tick in one GLib callback. Subsequent 30 Hz main-loop ticks perform no network/cache reads. Decoder capacity and actual acknowledgments come from Renderer.

HTTP requests never redirect and ignore ambient proxy variables. Metadata responses have a 1 MiB maximum and a 15-second deadline; WebSocket messages have the same bound. A media transfer requests only `/v1/media/{exact SHA256}` on the configured central origin, validates success/type/length, streams at most 64 KiB chunks into `Executor.acquire`, and has a 120-second total deadline. Only one transfer runs at a time; duplicate work is suppressed. Recheck current authority after every awaited/control boundary through Executor. Hash verification and quota admission belong to Cache. Retry acquisition failures after bounded 1/5/15/60-second backoff; no recursive or unbounded retry backlog.

The execution clock remains the disciplined OS UTC clock. Measure a short authenticated HTTP state request's monotonic RTT and compare the server UTC sample to the local midpoint. Establish TimeMapping only when RTT/2 plus observed clock difference is within its 100 ms limit; otherwise report unhealthy clock and withhold readiness. Resample at most ten seconds apart; server messages never silently set system time. Chrony is an appliance service. A disconnect preserves only existing Executor lease semantics; reconnection fetches current authority before new grants. A 401 re-enrolls with the durable key; a retired-key refusal remains visible and cannot create a new identity to evade retirement.

Send readiness at least twice per second while a Plan is active, including decoder/capacity failures. Observations are bounded and forwarded with their actual sample/draw time; never relabel download or preroll as presentation. A current-state response carries configuration, optional Plan, Commit and Revocation arrays, and server time. Validate neutral models and apply configuration, Plan, revocations, then compatible commits. An absent Plan is not new execution authority; existing leases expire normally. Invalid/stale messages cause a coded reconnect and cannot crash the GTK loop. Shutdown cancels transfers, waits for worker cleanup, closes sockets and native resources, and leaves durable cache/journal reconciliation to the next fresh epoch.

Tests inject dispatch, clock, renderer and transports for reconnect/rotation, bounded bodies, malicious redirects, cancellation during download, stale grant/revocation, and volatile registration. At least one real central HTTP session must demonstrate enrollment, offered exact-byte acquisition, readiness-bound commitment, application draw observations, outage and rejoin. The Linux/native image and physical PXE/Output tests remain distinct evidence.

Implemented entry point: `python -m player.service --config /etc/photo-wall/public.json`. The flat public file has exactly these fields (defaults shown for resource limits; deployment supplies its public CA and central origin):

```json
{
  "schema": 1,
  "central_origin": "https://photo-wall.example",
  "ca_file": "/etc/photo-wall/ca.pem",
  "state_dir": "/var/lib/photo-wall/player",
  "cache_bytes": 536870912,
  "allow_http": false,
  "decoder_limit": 4,
  "texture_budget": 536870912
}
```

Bootstrap/release configuration is a separate file and cannot add fields to this service configuration. `ca_file=null` uses the system trust store; the appliance builder supplies the fixed public CA path. The Python API is `PlayerService(config, identity, outputs, renderer, dispatcher, ...)`. Construction and `start()` occur on the Renderer thread; `tick_main()` belongs to that same thread. `GLibDispatcher` schedules at most four callbacks and returns a `concurrent.futures.Future`; the network loop awaits application instead of blocking GLib. Tests may inject HTTP transport, WebSocket connector, Clock, cache/Executor factories and runtime health paths. Only the runtime entry point imports GTK/GStreamer bindings. The service, identity and connector modules import no central or upstream media package.

The service polls authenticated state and sends readiness on a half-second cadence while healthy; WebSocket state adds prompt changes. A separate bounded observation sender prevents slow observation responses from blocking readiness. Both observation queues hold at most 128 entries, preserve actual timestamps and discard obsolete Plan/epoch entries; main-thread snapshots keep the latest observation per assignment. An observation/readiness race returning HTTP 409 fetches current state without rotating identity. HTTP 401 triggers same-key re-enrollment. Connection and acquisition retries use 1/5/15/60 seconds; a connection healthy for 30 seconds resets its retry history. State is never coalesced across authority changes. The service checks `PlayerConfiguration.authorizes` on every transfer boundary, in addition to Executor's admission and completion checks.

The systemd unit uses `ProtectHome=read-only` with `InaccessiblePaths=-/home -/root`. This keeps `/run/user` visible, as required for the logind-owned Wayland socket, while hiding unrelated home trees. `ProtectHome=yes` is unsuitable here because systemd also makes `/run/user` inaccessible; the [Ubuntu Noble systemd.exec contract](https://manpages.ubuntu.com/manpages/noble/man5/systemd.exec.5.html) defines that behavior. `RuntimeDirectory=photo-wall/player` creates the root-owned `0755` parent and the `wall`-owned `0700` child before per-command mount namespaces are applied, so the required `ReadWritePaths=/run/photo-wall/player` exists for every startup command. The unit's writable exceptions remain limited to the Player health child and its durable state directory. These source corrections address the service's Wayland and runtime-directory namespace contracts; a hosted namespace boot is still required to qualify the resulting image and identify any independent `226/NAMESPACE` failure.

The sole media worker reconciles ownership at most once per two seconds and verifies secured bytes every ten seconds, as well as after reported decode/integrity failures. These operations serialize with acquisition. A long bounded transfer can defer maintenance until the worker is free. Missing/corrupt files revoke readiness and become acquisition work again. HTTP errors, authority changes and shutdown stop the chunk bridge and await worker cleanup; no response error leaves its consumer waiting indefinitely. Clock samples delayed over one second in the dispatch queue, clock steps, excessive RTT and excessive central/local disagreement all withhold readiness.

Private identity storage includes a small exclusive write/fsync/unlink/directory-fsync probe even when a valid key already exists. A readable valid key on unusable storage remains the same signed identity but declares volatile persistence. An invalid existing key remains untouched. If cache/journal initialization fails after the probe, the next registration uses the same key with signed volatile persistence and no Executor. Durable keys and execution journals are private files; bearer tokens never reach disk.

`output_discovery.output_app_id("HDMI-A-1")` returns `photo-wall-HDMI-A-1`; the compositor and native entry point share that mapping. Card enumeration prefixes are removed. Ambiguous connector identities or more than two HDMI connectors fail discovery with a bounded local code. Available/preferred DRM `modes` are never reported as current pixel dimensions: reports use zero until an authoritative current mode is available, and native rendering uses its actual GTK framebuffer. Disconnected connectors remain registration observations; only connected connectors receive native surfaces. With no native display, the service remains visible through registration and reports unavailable capacity instead of fabricated draw acknowledgment. Discovery currently occurs at process startup; live topology changes require supervisor integration or a process restart.

After successful current-state reconciliation, the service atomically replaces `/run/photo-wall/player/service-health.json` with `boot_id`, `sampled_monotonic`, `player_id`, `authority_epoch`, `persistence` and `healthy`. The parent `/run/photo-wall` remains root-owned for the bootstrap's `0600` boot report; only its `player/` child is writable by the Player. There is no token or key in this file. Healthy requires durable execution storage, current reconciled configuration, a fresh safe clock mapping and initialized native surface capacity; an unbound Player with working connected native Outputs may be healthy. Network failure and shutdown write unhealthy. The updater independently requires the current Linux boot identity and a stable health interval; this file grants no playback authority.

Validation on 2026-09-05: 49 scoped tests passed with `.venv/bin/python scripts/test_local.py -q tests/test_player_service.py`. This includes 48 portable tests and one actual loopback TCP HTTP/WebSocket session backed by an isolated real PostgreSQL schema and generated local media bytes: registration before binding, exact central gateway acquisition, readiness-bound commitment, application observation, injected HTTP 503 continuity, real obsolete-observation HTTP 409 renewal recovery, same-key epoch change and old-token rejection. The integration uses `RecordingRenderer` and a controllable clock. Its generated byte fixture tests transport/storage and does not claim native decoding, physical HDMI timing, PXE boot, Pi capacity, or actual server shutdown. The [native renderer](module-native-renderer.md) and [real upstream fixture](module-immich-fixture.md) own their separate evidence.
