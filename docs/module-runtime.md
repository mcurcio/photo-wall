# Deterministic Runtime module

Status: design accepted for the bounded implementation below; only simulated evidence is claimed.
Owner: `central/runtime.py`. Policy comes from [the MVP time decision](decisions/0001-mvp-time-recovery-and-module-contracts.md), [requirements](requirements.md#run-behavior), and [execution contract](execution-contract.md).

## Responsibility and boundaries

Runtime admits and deduplicates activations, adopts immutable complete Scene trees, reconciles concrete UTC Program windows, advances Run lifecycles, and resolves current contributions per typed target. It owns no database, clock, transport, catalog, selection, preparation, or physical device. A caller supplies finite UTC seconds and persists `export_state()` transactionally with admission. `restore()` recreates identities, adopted trees, activation results and queues. Definition updates affect subsequent root admissions; live source results belong to the catalog and remain changeable.

The public input models are frozen Pydantic `Contribution`, `Child`, `Scene`, and `Program`. A Contribution explicitly targets `frame:<id>` or `actuator:<id>` and describes media (source/asset references and an optional fixed role), opaque black, or a continuous normalized actuator ramp. No implied command comes from membership. Source references identify versioned centrally owned source definitions; Runtime never interprets them. A Scene contains its own contributions, embedded child Scene definitions with delays, a positive cycle length, loop/duration configuration, optional outro duration/contributions, and optional visibility protection. Children retain their authored target/role bindings. Frame targets are explicit IDs and Runtime does not require a matching live equipment row when saving a Scene; a missing Frame target can remain as future recovery intent and cannot execute until Central has an eligible binding. The operator Frame-delete guard separately protects saved Scene roots and queued activations that already refer to an existing Frame.

## Time and lifecycle contract

Run logical position is elapsed UTC since admission (or a child's scheduled start). A cycle's half-open interval supplies Planner with stable assignment timing. Nonloop Scenes execute one cycle; looping Scenes execute new cycles until natural completion is requested. Optional `duration_seconds` and Program expiry request natural completion at their exact UTC instant. A natural stop starts no cycle or delayed child at or after its instant, completes the cycle already in flight, recursively requests active descendants to finish their current work, waits for those descendants, then executes its own optional outro. Delayed children not yet started are not in-flight work. Projection/prefetch never extends lifetime. Cancellation immediately cancels only the selected Run subtree and skips outros.

Each Program window is an independent activation, including contiguous windows of the same Program; the manual repeat policy does not suppress a successor while its predecessor finishes. An admitted window snapshots its end, so a later save of the Program never rewrites a Run already admitted. Removing a Program forgets it first, then requests natural completion of its active roots, so no window of it starts at that instant. Windows wholly missed before the first observation are not replayed. How a window is worked out is [House time and repeating Programs](#house-time-and-repeating-programs). Advancing an already-running Runtime processes intervening Program boundaries, retaining their exact intended times. Its successor is independently admitted at its own boundary while the old root finishes; an independent overlay retains its identity/lifetime. Equal priority resolves by later root admission, then later child admission within that root. Children override their parent only where they currently contribute. A newly protected root must also outrank any overlapping higher-priority root; protection does not implicitly raise priority. Protected roots reserve the union of participating Frames (including delayed descendants) against a conflicting root unless explicit `force=True` is supplied. Protection requested by a descendant reserves that descendant's Frame union in its admitted root, including before delayed start; unprotected sibling Frames stay independently addressable. Actuators arbitrate independently and are not visibility reservations.

`advance(now)` is the only clock-driven current lifecycle mutation. Explicit activation/completion/cancellation first reconcile to their supplied `now`. Calls cannot move time backwards. `project(now)` restores an exported copy, advances that copy, and returns the same immutable intent view without changing present state, queued requests, current children, or actuator output. Programs and children use deterministic derived Run IDs so projection agrees with later advancement. The output distinguishes all currently contributing layers from per-target winners and the participant union. Layers expose adopted Scene revision, Run/root identity, admission ordering, logical and cycle position, exact cycle or outro interval, fixed media references, opacity, and current ramp value.

`operator_projection(now, *, max_events=10000)` is the operator console's read (`GET /v1/operator/runtime`). Like `project`, it advances a restored copy under the same `max_events` transition budget and leaves present state untouched. It returns `current` with its Runs filtered to live Runs plus those ended within the last `OPERATOR_HISTORY_SECONDS` (24 h); `protected_frames`, mapping each served Run that protects at least one frame to those targets, computed only here and never on the scheduler's path; `program_windows`, mapping each Program to its current and next window (start and end as instants and as house-time strings, and the window's `Admission`, None until it has one); and `default_scene`. The read leaves stored state alone; Runtime itself forgets what ended before the same bound ([Admission and bounded state](#admission-and-bounded-state)). Its operator wording is owned by [pass 2 slice 3, §8](operator-console-ux-pass2-showrunner.md#8-what-central-adds-read-only-frozen-for-bead-3a-3).

## Scene definitions

`set_scene(scene)` is the one Scene write path (both operator Scene writes and authored configuration go through it). It refuses a save whose `revision` is at or below the stored Scene's, unless the save equals the stored Scene exactly (`SceneWriteRefused` "changed", HTTP 409 with the stored Scene as `current`), and a Transition too long for its photos (`SceneWriteRefused` "transition_too_long", HTTP 422 with `max_seconds`; [the bound](execution-contract.md#a-scenes-transition-when-a-photo-starts-to-show)). An identical retry is therefore accepted, and a save built from an older copy never silently replaces a newer one. No expected-revision field exists: the Scene's own `revision` is the precondition. Nothing is stored on refusal. The Scene's `transition` (style and seconds) is its one fade; Runtime turns it into each photo's start and fades ([execution contract](execution-contract.md#a-scenes-transition-when-a-photo-starts-to-show)). The operator wording is owned by [pass 2 slice 3, §13](operator-console-ux-pass2-showrunner.md#13-scene-view-and-lossless-edit-3b).

Two commands use it, one per route, and both answer a `SceneOnWall`: the Scene as stored and its `earlier_version`, the root Runs still playing an older revision (each a `RunRef`: `run_id`, `scene_revision`, `started_by` "schedule" or "show_now"; not a Run already finishing, and never the Default Scene's, which restarts itself on a save) and the queued Show now activations holding an older copy. Both empty: the wall already follows the saved revision.

- **Save** (`save_scene`, `PUT /v1/operator/scenes/{id}` and `…/authored`) stores the Scene only (requirements: "Authored configuration edits default to the next Run"). Admitted Runs and queued activations keep the Scene tree they captured, so it affects only later admissions; the answer names what still plays the earlier version, and the console says so.
- **Save and apply now** (`save_scene_and_apply_now`, `POST …/apply-now` and `…/authored/apply-now`, the same body) stores it, then replaces each Run playing an earlier version at once: its successor, on the stored revision, is admitted over it, and only then does it finish gracefully beneath it, so the change cross-fades over the photo showing. A successor refused (protection) leaves its Run playing and still listed. A successor takes its predecessor's place in the stacking order, just above it (`_place_over`), so a Run admitted after the predecessor at the same priority stays on top. A Schedule's successor keeps its window's end; a Show now's keeps its original start, so it ends there plus the new duration. Queued activations take the new copy. An identical retry, or pressing it on an unchanged Scene, replaces only what is earlier. It changes the wall at once rather than at the end of the photo showing: waiting needs a new Run's first photo to show before its Run starts, the hand-over cross-fade the owner put off (2026-10-15: "Not right now").

`delete_scene(scene_id, expected_revision)` removes only the stored definition. Its separate operator DELETE route requires the revision read with the card and refuses a stale request. It also refuses while a Program references the Scene, an active Run or queued activation has it in its captured tree, or another stored Scene embeds it; the 409 response names each blocking identifier. Completed Run snapshots and activation history are retained. Deletion therefore changes future choices without altering an execution already admitted.

## House time and repeating Programs

Roadmap 2b ([0021](decisions/0021-power-timetable-and-repeating-schedules.md)). A **Program** (the console's Schedule) is a Scene, a **When** and a priority: `{program_id, name, scene_id, when, priority, revision}`. A When is the days a window starts on, a start and an end, each a clock time or sunrise/sunset plus or minus minutes; an end at or before the start is on the next day. Its windows are worked out in house time (Settings › House's zone and location) by the one calculator, `central/house_time/calculator.py`, and never stored: a skipped daylight-saving time moves forward by the gap, a repeated one takes its first occurrence, a day with no sunrise or sunset has no window, and one When's windows never overlap. Runtime takes the `HouseTime` at construction and `restore`; the Runtime store reads it in the same transaction (`central/infra/house_store.py` `house_time_in`).

- **Window identity** is `program:<program_id>:<revision>:<start>`, so a saved rule's windows never alias the previous rule's. External activation ids cannot use the reserved `program:` or `default:` prefixes.
- **Priority** is Normal (the default), Special event or Always wins; the Default Scene ranks below all three and below any operator request (`DEFAULT_SCENE_RANK` is -1; `activate` and the route accept priority 0 and up), so it never wins a tie. The tie rule is Runtime's: the request admitted last wins.
- **The Default Scene** (E5, `set_default_scene`) plays wherever no Program does: one perpetual Run at the lowest rank, its Scene repeated until replaced (a Scene that does not repeat by itself, or has a duration, still repeats as the Default Scene), identity `default:<scene_id>:<choice revision>:<Scene revision>:<start>`, admitted whenever none under the current prefix is active and no protection refuses it (a refusal is not recorded; it is retried at the next event). A Run under an older prefix, from an earlier choice or an earlier revision of its Scene, finishes gracefully and the current one is admitted: changing the choice and editing its Scene both take effect at once, as the next Run (requirements: authored edits apply from the next Run); "none" is allowed.
- **Create** (`create_program`, `POST /v1/operator/programs`) admits the window covering now, if any, at once, from now to its end under its own identity (owner, 2026-10-12: "Start right away, for the rest of tonight's window"); later windows follow from now.
- **Save** (`save_program`, `PUT /v1/operator/programs/{id}`) applies from the next window: the window playing now keeps its end (R10). **Save and apply now** (`save_program_and_apply_now`, `POST …/apply-now`) finishes the Program's playing Runs gracefully at now and admits the new rule's window covering now, if any, under its own identity; the Runs it replaces are left out of the protection check. Both compare the whole expected Program (409 `changed` with the current one; an identical retry is idempotent) and refuse an unknown Scene, a When with no days, or a sun time while the house has no location.
- **A house zone or location change** applies from each Program's next window: a window is never admitted before the instant Runtime has processed, so a window the change moves into the past is not played backdated, and the window playing keeps its end.
- **At deploy** migration 089 ends today's Programs (they were single windows timed in the browser's zone, which Central never recorded); Runs already admitted keep their snapshot end. No backwards compatibility.

Routes: `central/program_routes.py`. Why explains the winner from Runtime's view and never decides ([execution contract](execution-contract.md#why-is-this-playing)).

## Admission and bounded state

`activate` records a result for each activation ID; externally supplied IDs cannot use the reserved `program:` or `default:` prefixes, and root/child Run hashes use separate identity namespaces; repeating the same identity returns that result without launching again. Matching repeat scope is the active root Scene ID. Default `ignore` references that active root. `restart` cancels matching roots before replacement (subject to other protected roots). `queue` snapshots at enqueue, accepts at most 16 waiting requests, and requires finite caller-supplied expiry. Expired entries never launch. Queued work starts when its same-Scene predecessor releases and protection permits it. A protected denial is a durable result; retry requires a new activation ID. A `protected_frames` or `protection_not_visible` rejection carries `blocking_run_id`, the root Run whose protection refused it; the field is optional, so admissions stored before it existed still restore.

Runtime keeps active children and retained root Run records, with completed descendants pruned once their lifecycle has propagated upward. Queue size is bounded. **One retention rule** (`Runtime._forget`, at every advance) bounds the rest: a root Run that ended, and whose Program window (if any) ended, more than `OPERATOR_HISTORY_SECONDS` (24 h) ago is forgotten with its admission, and a refused Program window's admission is forgotten once its window ended that long ago. Repeating Programs and the Default Scene therefore leave a state that stops growing within a day or so, however long the wall runs (`tests/test_runtime.py`, three weeks of Schedules). The cost: an operator retry of an activation id whose Run ended more than a day ago is a new request.

## Effects and failures

The recording actuator adapter accepts a current Runtime view plus an explicit set of authorized Run IDs, rejects views whose instant differs from execution time, and applies only winning authorized actuator contributions. It records current values only; it never walks hidden layers or replays intermediate ramp values. Omitted targets produce no reset. Runtime supports explicit `finish` and `cancel` so coordination can route meaningful failures to lifecycle ownership; preparation and secured-file state cannot implicitly finish or extend a Run.

## Verification scope

Portable tests cover an accelerated December/January successor under an independent overlay, lamp-covered and lamp-uncovered cases, current media/ramp reveal, fixed nested roles and delayed child membership, natural finish versus downward cancellation and future projection, admitted-definition immutability, repeats/protection and queue expiry/capacity, validation, and serialization/restart idempotency. This module cannot establish media readiness, actual rendering, visible synchronization, real Immich behavior, PXE, or appliance continuity.

Verified on the development host with Python 3.12.11: `.venv/bin/python -m pytest tests/test_runtime.py -q` and `.venv/bin/python -m ruff check central/runtime.py tests/test_runtime.py`. The host `uv run` executable panics in macOS system configuration in this sandbox; the already-established repository environment runs the checks directly. These checks are simulated evidence only.

Focused independent review found and verified fixes for protected ownership release at an exact successor boundary, removal across an intervening Program start, and external activation identity collisions with derived child Runs. Two independent deterministic random exercises (200 and 300 nested traces) also compared coarse and incremental lifecycle advancement with identical durable state.

Final focused verification on 2026-09-05: 28 Runtime tests passed; combined Runtime/shared-contract check passed 35 tests. Independent reviewer reran 9 focused regressions and the original Program-removal/identity-collision reproductions after the fixes, with no remaining material finding in that review scope. Focused Ruff and whitespace checks passed. Scheduled Programs respect existing visibility protection; the calendar demo uses unprotected background Scenes and an independent overlay.
