## Proposed architecture for review

This is a design proposal, not a claim that the current code implements it. Keep one authority for each kind of state and expose narrow interfaces between domains:

| Domain | Owns | Contract to its neighbors | Failure rule |
|---|---|---|---|
| Base OS agent | This boot's reachability, boot phase, package install attempt, app process status and a short on-screen failure page. No Frame authority or durable update slot. | A small, versioned **OS observation channel** using shared Central discovery; a separate boot-scoped command channel is gated on an explicit identity/authorization design. | Continues checking in while the app is absent, upgrading or crashing. A Central outage retains only current local boot facts and does not imply playback authority. |
| Central fleet control | Desired OS/app versions, release availability, per-device update attempts and observed boot/app reports. | Keep OS observation/command and Player app execution channels separate in endpoint, credential, protocol and authority; distinguish app control acceptance, applicable plan readiness and observed presentation; serve compatible exact `.deb` bytes and desired state. | A protocol rejection is named and visible. An old app cannot suppress the independent base observation. An observational serial is not proof of device identity. |
| Player app | Fresh-session control, media readiness, execution and Output observations. | Negotiates an app protocol/capability version on its own channel, receives only current authority and exact media from Central, reports control-state acceptance, applicable plan readiness and Output observation. | An incompatible app is directed to upgrade rather than silently classed as offline; old grants remain rejected. |
| Media worker | Upstream credentials, verified metadata ingestion, thumbnail/poster acquisition and media preparation. | Produces bounded batches and durable cursor/observation data; never sends an Immich URL or credential to a Player. | Upstream or paging failure preserves a named incomplete/stale observation; large cardinality is not an error. |
| Source catalog and planner | Immutable Source definitions, discovered membership/progress, eligibility queries, secured assignments and current preparation windows. | Bounded candidate pages to planner and operator views, with freshness/completeness markers. | Partial discovery is not reported as an empty full Source; secured content remains fixed for its execution. |
| Calibration session and renderer | Central owns a leased pending draft and committed revision; Player owns currently applied pending geometry and diagnostic pixels. | Fast, sequenced pending updates and applied acknowledgments outside execution plan identity; commit uses binding generation and revision checks. | Disconnect, lease expiry or rebind removes pending state and overlay and restores committed output. |

### Fleet state and update path

The [control-protocol design](player-protocol-compatibility-design.md) owns the F0 compatibility proposal. The [fleet-control design](player-fleet-control-design.md) owns the base check-in, layered status, app policy/update, and base-health proposals for F1–F4/F6; the [red/blue refinement](player-fleet-red-blue-refinement.md) owns their cross-layer trust, transaction, maintenance and qualification gates. These are review drafts: they distinguish desired, offered, locally installed, exact process incarnation, app control accepted, applicable plan ready and output observed. OS observation and OS command are separate from Player execution authority; an observational serial claim cannot authorize a command or automatic health promotion.

### Source discovery and selection path

Treat a Source as an immutable **query**, not a fully materialized array. The worker maintains a **paged, evictable metadata index** per connection or canonical query, with durable traversal checkpoints, observation time and a small protected set for selected/secured assets. It does not mirror every upstream asset into PostgreSQL. Several Sources reuse observed pages rather than independently storing duplicate full catalogs. Source evaluation and hard Frame compatibility use one central query service that returns a bounded `CandidatePage` plus `observed_at`, progress and completeness. The planner requests bounded eligible windows and rotates fairly across old and new matches; the operator gallery queries the same selection data and can request older pages on demand. Only selected/lookahead assets enter the central media cache and Player delivery path.

The discovery adapter must prove that every upstream asset can eventually be visited and removals detected. The current Immich metadata search sorts by capture time without a stable tie-break, so continuing offset pages is not sufficient. The design gate must validate a stable cursor or change feed, a different upstream enumeration API, or a provider-side extension. Time-window partitioning is valid only if even a >1,000-item equal-timestamp partition can be split without loss. Until such a traversal is proven, show **discovery incomplete** and a lower-bound observed count; do not claim an exact total or silently omit assets. Network, memory, byte and request budgets remain bounded by yielding and resuming work, without turning Source size into `source_limit`.

The operator chooses a connection from a sanitized Central inventory before filters. Central requests the connection's supported facets and a bounded live preview through the worker. Saving the Source reuses the canonical query; subsequent refresh and the saved gallery share the same semantics. Thumbnails and video posters travel through an operator-only Central preview path, with a disposable bounded cache. An optional Immich deep link needs an explicit operator-only disclosure decision because the current runbook intentionally omits it; it never becomes a Player URL.

### Calibration data path

The UI opens a leased draft for one Frame, Output, binding generation and committed calibration revision. Every valid corner/crop edit gets a monotonic sequence; Central coalesces pending updates, sends the newest one over a fast path and returns the Player's **applied** sequence to the UI. The renderer applies pending geometry locally while keeping committed execution and media plans intact. The diagnostic overlay is drawn last, in physical output coordinates, so a wrong quad, black Scene or low gain cannot hide it. It labels physical Output bounds separately from virtual Frame bounds and identifies values as pending or committed.

Commit atomically checks the original binding generation and revision, publishes one committed revision and ends the draft. Revert, inactivity expiry, disconnect and rebind restore committed geometry and remove the diagnostic. The current preview route changes the binding embedded in plan identity; sending each pointer move there would churn offers and commitments ([regression](../tests/test_coordination.py)). The new session must be independent of plan identity, with controlled-clock tests for stale/out-of-order updates and physical latency/continuity qualification.
